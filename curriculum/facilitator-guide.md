# Facilitator guide

Bring the repository at an identified revision, one working local environment, a written copy of the worked case, and a second empty workspace for a replay. Read the chosen edition and run the installation and first mission from the root README. Mark the revision, commands, outputs and any credentials actually needed. Remove real credentials and customer or personal data from demos. Use an accessible text copy of each exercise and allow written defenses.

## Before the room opens

Have participants complete the first workbook table. Ask each to show one source and name the person who can reject the result. Choose a synthetic case when the owner cannot authorize the source. Pair an operator with a reviewer. The first presentation should fit on one screen: source, claim, proposed action and approval boundary.

## Facilitate the correction

1. Collect the learner's first decision before the assistant offers a solution. A participant can opt for a worked example. Record the assistance and reserve the first independent check for the transfer.
2. Activate a local workspace using the root quickstart. Have the learner inspect the proposed configuration before accepting writes. Run the chosen mission. Capture the actual artifact reference, evidence and command output.
3. Ask the reviewer to locate the strongest contrary source. Give the learner time to revise. Record both versions. Put possible changes to shared skills, policy and workflow defaults into review.
4. Introduce the edition's changed condition. Ask for an individual prediction, then run or replay. Allow an operator to stop or withhold action when available evidence no longer supports it.
5. Close with one owner, a seven-day repeat mission and a measurable acceptance condition. Give participants their records. Use only separately approved excerpts in group debriefs.

## Outcome review

Mark each row **observed**, **revise**, or **unobserved**. Record a file, a quote from the learner's defense, or a timestamped run for every observed claim. Any unresolved source-use or authorization question puts the operational decision on hold. Average scores hide missing evidence.

| Criterion | Observation needed | Return for revision when |
| --- | --- | --- |
| Useful outcome | Named beneficiary can use or reject a concrete artifact against the agreed check | Only commentary or screenshots exist |
| System behavior | Versioned configuration replays on allowed inputs and stops on the changed condition where appropriate | Rerun relies on an undocumented credential, prompt or manual correction |
| Human judgment | Learner explains a tradeoff and predicts what changes on a new input | Only agent-generated explanations or copied answers are offered |
| Source and authority | Reader can trace consequential claims and identify a human approver | Approval, rights or fact is inferred from fluent output |
| Improvement | Reviewed candidate change has a baseline, next observation and owner | A change in wording is reported as a capability gain without a repeat test |

## Handoff and recovery

A second facilitator rehearses without the author in a blank working directory. Give them the learner edition and source case first, then the private facilitator key from the worked case. They should identify the unsupported recommendation, distinguish scope from observed behavior, run the root mission, and reproduce a changed-input decision. Record every time they need to ask the author. Resolve those points and repeat before describing the edition as independently delivered.

A missing model or plugin leaves the local CoE path and paper exercise available. If activation itself fails, record the error and continue only the judgment exercise. If a participant used an agent for the transfer answer, ask for another changed case or record human transfer as unobserved. Successful machine checks establish structural behavior; a participant outcome requires an actual learner and a reviewer.
